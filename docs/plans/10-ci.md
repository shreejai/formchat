# Plan: Issue #10: CI and secret scanning

## Context
CI for formchat: typecheck, lint, test and build on every PR and every push to `main`; gitleaks over the full history; evals only on demand, because they cost money. No app code changes and no new dependencies. Work happens on `feat/ci`.

## Findings
- `npm ci` installs cleanly without `--legacy-peer-deps` (clean install from the committed lockfile, Node 22.22.1 / npm 10.9.4). CI uses plain `npm ci`, with a comment explaining why the flag isn't there.
- `next typegen` is available in Next 16.4.3.
- Nothing reads `process.env` yet on this branch.

## Changes
1. **`package.json`**: only the `typecheck` line changes, to `next typegen && tsc --noEmit`. This makes typecheck work in fresh checkouts and CI without a prior build. Branch #9 is editing the other lines of this file at the same time.
2. **`.nvmrc`**: `22.22.1`.
3. **`.github/workflows/ci.yml`** (on `pull_request`, and `push` to `main`; `contents: read`; superseded runs cancelled):
   - `build`: setup-node from `.nvmrc` with npm cache → `npm ci` → typecheck → lint → test → `next build`.
   - `secrets`: checkout with `fetch-depth: 0`, install the gitleaks v8.30.1 release binary (checksum-verified), run `gitleaks git --redact --verbose`. Any finding fails the build. It uses the CLI instead of `gitleaks-action`, which needs a license key for org repos, and instead of the Docker image, which can fail with git "dubious ownership" errors on mounted checkouts.
4. **`.github/workflows/evals.yml`**: `workflow_dispatch`, or `pull_request` (`labeled`/`opened`/`synchronize`/`reopened`) when the PR has the `run-evals` label. Runs `npm ci` and `npm run eval` with `OPENAI_API_KEY` from repo secrets. `npm run eval` arrives with #9, so this workflow works once that merges.
5. **`README.md`**: a "CI" section covering what runs and when. It says environment variables are listed in `.env.example`.
